# Карта репозитория

Этот файл агент читает перед первым походом в код. Он нужен, чтобы агент не
искал вслепую: без карты поиск по большому репозиторию выходит долгим и
неточным. Замените текст ниже на описание своей кодовой базы.

Если кодовая база не подключена (переменная `GD_CODE_REPO` не задана), файл
можно не заполнять — агент к нему не обратится.

## Стек

Языки, фреймворки, движок, менеджер пакетов. Одним списком.

## Где что лежит

Таблица «путь → что там». Достаточно верхнего уровня и заметных подсистем.

| Путь | Что там |
|---|---|
| `src/` | Прикладной код |
| `src/api/` | HTTP-ручки |
| `tests/` | Тесты |

## Куда не ходить

Вендорные каталоги, сгенерированный код, крупные бинарники — всё, где поиск
только тратит время: `node_modules/`, `vendor/`, `build/`, `.venv/` и подобное.

## Где искать значения

Куда вынесены настройки, константы и цифры — конфиги, миграции, файлы данных.
Важно, если в коде они не хардкодятся: агент должен смотреть в источник, а не
в дефолты полей.

## Договорённости в коде

Соглашения об именовании, слоях, обработке ошибок — то, что помогает понять
чужой файл быстрее.
