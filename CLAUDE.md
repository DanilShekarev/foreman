# CLAUDE.md

Указания для Claude Code при работе над gd-assist.

## Что это

Внутренний сайт для геймдизайнеров студии: чаты (каналы / ЛС / личный чат с
агентом) + markdown-волт диздоков под git + агент на Claude Agent SDK, который
читает и правит волт и читает код Unity-проекта
`D:\work\pixup\slopebuildergame` (только чтение).

Комментарии, UI и коммиты — по-русски. Тестов нет; проверка — запуск и глаз.
Пользователь запускает сервер сам — не поднимай его автономно.

## Команды

```bash
start.bat
```
Первый запуск создаёт venv (Python 3.10), ставит зависимости, сеет админа
(пароль печатается в консоль) и канал «Общий», инициализирует git-репо волта.
Хост 0.0.0.0:8010 — доступ по LAN.

```bash
.venv\Scripts\python.exe -m py_compile server.py store.py agent.py vaultlib.py gitops.py prompts.py docx_io.py common.py
```

## Архитектура: что важно не сломать

**Один воркер uvicorn, без reload.** Агент-сессии (`agent.py: manager`) живут
в процессе — словарь `chat_id -> AgentSession`, каждая держит подпроцесс CLI.

**store.py не знает про FastAPI** (дисциплина из D:\Agent\kanban): любая
запись — внутри `store.write_tx()` (BEGIN IMMEDIATE), `init_db()` — вне
транзакции, соединение на запрос.

**Права агента — только PreToolUse-хуками** (`agent.py: _make_guards`).
`can_use_tool` затеняется `allowed_tools` и молча не работает
(CanUseToolShadowedWarning). Bash агенту запрещён целиком: git-коммиты делает
сервер (`gitops.py`), не агент. Unity-код read-only автоматически — его нет
в write-корнях.

**Агент читает НЕ рабочую копию Unity-проекта, а зеркало main**
(`unity_mirror.py` → `data/unity-mirror`): shallow (--depth 1) + partial
(--filter=blob:none) клон с sparse-checkout только Assets/_SlopeBuilder_;
истории в зеркале нет — агент читает текущий срез, откаты делает git волта.
Сервер подтягивает local main раз в `GD_MIRROR_SYNC_MIN` минут (fetch из
рабочей копии читает только refs, человеку там не мешает). Незакоммиченные
правки и другие ветки агенту не видны; `vaultlib.unity_root()` отдаёт зеркало,
а до первого клона — рабочую копию. Рабочая копия при живом зеркале запрещена
read-гардом. Источник клона — file:// URL: с голым путём git включает
хардлинк-режим и игнорирует --depth.

Для partial-fetch в РАБОЧЕМ репо игры включены две локальные опции
(`git config uploadpack.allowFilter true`, `uploadpack.allowAnySHA1InWant
true`) — они лишь разрешают отдавать фильтрованные выборки и в коммиты не
попадают, но после переклонирования slopebuildergame их нужно включить снова,
иначе .git зеркала распухнет до полного снапшота.

**Правила видимости путей волта — только в `vaultlib.py`** (can_see/can_write/
agent_scopes). Ими пользуются и хуки агента, и HTTP-ручки, и дерево UI. Новую
проверку писать туда, а не в server.py.

**Волт — отдельный git-репозиторий** (`vault/`, в .gitignore приложения).
Все вызовы git — через `gitops.py` под одним asyncio.Lock. Ход агента коммитит
только тронутые файлы (пути собираются из ToolUseBlock), хеш лежит в
`agent_turns.commit_hash` — diff хода это `git show <hash>`.

**Стриминг — NDJSON поверх POST** (`/api/chats/{id}/send`), не SSE и не WS.
`AuthMiddleware` — pure-ASGI: BaseHTTPMiddleware буферизовал бы стрим.
Остальные участники чата получают обновления поллингом `/api/changes?since=`
(таблица `changes`), стримящийся текст агента дописывается в `messages`
с троттлингом ~1.5 с.

**Авторизация SDK — подписочная** (`common.py: setup_auth`): токен
`claude setup-token`. Ищется по списку путей: `GD_CLAUDE_TOKEN_FILE` → свой
`auth_token.txt` (в .gitignore) → общий `D:\Agent\agent-game\auth_token.txt`
(токен один на все агентные проекты). Файл читается при каждом создании
сессии — перевыпустил токен, сервер перезапускать не надо.

**Resume:** `sdk_session_id` из ResultMessage хранится в `agent_sessions`;
клиент чата закрывается по 30-минутному бездействию и пересоздаётся с
`resume` — контекст переживает и таймаут, и рестарт сервера.

**Карта Unity-проекта** — `vault_seed/UNITY_PROJECT_MAP.md`, сеется в волт при
первом старте. Промпт агента (`prompts.py`) велит начинать разбор кода с неё.

**Фронтенд** — ванильный JS без сборки и CDN, пути к API относительные
(работает и за реверс-прокси-префиксом). Markdown и diff рендерятся своими
мини-функциями (`web/md.js`, `web/diff.js`); сторонние библиотеки — только
вендорингом в `web/vendor/` (сейчас там CodeMirror 5 для редактора; без этих
файлов редактор тихо откатывается на textarea).

**Кэширование статики** (проект живёт в интернете за danishe.sbs/gd):
`index.html` отдаётся роутом `index_page` с `?v=<mtime>` на каждом js/css и
`no-cache`; остальная статика — `immutable` на год (`ImmutableStatic`).
Менять схему ссылок на ассеты — только через `_ASSET_RE`. Новые css/js в
index.html подхватываются сами; ассеты, подключаемые МИМО index.html, так
кэшировать нельзя. Загрузки чата (`/api/upload/{id}`) тоже `immutable` —
имя файла случайное, содержимое не меняется. Сжатие и HTTP/2 — на Caddy.

**Темы** — токены в `:root` style.css, светлая — `[data-theme="light"]`.
Атрибут на `<html>` ставит инлайн-скрипт в `<head>` index.html ДО загрузки
стилей (иначе вспышка тёмного), выбор в localStorage `gd_theme`. Пользователь
требует визуал уровня «серьёзного ПО» — новые элементы UI строить на токенах,
не хардкодить цвета.

## Грабли Windows (уже наступлено в соседних проектах)

- `common.py` при импорте чинит UTF-8 в консоли и выключает QuickEdit (клик
  мышью в cmd замораживает процесс вместе с пайпами SDK).
- Транспорт SDK — построчный JSON, 1 МБ на строку; если агент начнёт читать
  огромные .asset — поднять `max_buffer_size` в опциях.
- curl на localhost у пользователя может врать из-за VPN — доверять логам
  сервера.
