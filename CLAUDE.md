# CLAUDE.md

Указания для Claude Code при работе над Foreman.

## Что это

Foreman — self-hosted платформа для командной работы: чаты (каналы / ЛС /
личный чат с агентом) + markdown-волт базы знаний под git + агент, который
читает и правит волт и читает зеркало кодовой базы проекта (только чтение).

Комментарии, UI и коммиты — по-русски. Тестов нет; проверка — запуск и глаз.
Пользователь запускает сервер сам — не поднимай его автономно.

## Команды

```bash
start.bat      # Windows; Linux/macOS — ./start.sh
```
Первый запуск создаёт venv (Python 3.10+), ставит зависимости, сеет админа
(пароль печатается в консоль) и канал «Общий», инициализирует git-репо волта.
Настройки — в `.env` (образец `.env.example`, парсер — `common.load_env`,
реальное окружение приоритетнее файла).

```bash
.venv\Scripts\python.exe -m py_compile server.py store.py agent.py agent_openai.py agent_tools.py llm.py vaultlib.py gitops.py prompts.py docx_io.py common.py code_mirror.py transcribe_call.py
```

## Архитектура: что важно не сломать

**Один воркер uvicorn, без reload.** Агент-сессии (`agent.py: manager`) живут
в процессе — словарь `chat_id -> AgentSession`, каждая держит подпроцесс CLI.

**store.py не знает про FastAPI**: любая запись — внутри `store.write_tx()`
(BEGIN IMMEDIATE), `init_db()` — вне транзакции, соединение на запрос.
Миграции схемы — только догоняющие и идемпотентные (PRAGMA table_info +
ALTER TABLE в init_db).

**Два движка агента (#49).** Чем считать ход, решает провайдер выбранной
моделью (`llm.py`, реестр в таблице `llm_providers`, правит админ в UI →
«Модели агента»):

* `kind='claude'` — `ClaudeSDKClient`, подписочный CLI.
* `kind='openai'` — свой цикл `agent_openai.py` поверх OpenAI-совместимого
  API (OpenRouter, локальный сервер). Транспорт — httpx2 напрямую, без
  клиента openai: он поверх httpx2 сыплет трейсами при закрытии SSE.

Модель чата хранится в `chats.model` как «ключ-провайдера:id-модели» и
режется по ПЕРВОМУ двоеточию (id у OpenRouter сами двоеточные:
`z-ai/glm-5.2:free`); значение без двоеточия — из времён единственного
провайдера, читается как `claude:`. Ключ провайдера можно не класть в базу:
значение вида `env:OPENROUTER_API_KEY` читается из окружения, наружу ключи
не отдаются никогда (только `has_key`).

Дочитывать SSE после `data: [DONE]` обязательно: брошенное на середине тело
httpcore добивает сборщиком мусора и печатает в лог трейс «generator didn't
stop after athrow()».

**Инструменты агента — один список на оба движка** (`agent_tools.py`).
MCP-инструменты (fs/kanban/threads) описаны декоратором `@tool` из SDK;
Claude-движок заворачивает их в SDK-MCP-серверы, свой цикл зовёт `handler`
напрямую и отдаёт модели JSON-схемы. Там же нативные `Read/Glob/Grep/Edit/
Write` для своего цикла. Имена и ключи аргументов совпадают с инструментами
Claude Code: на них завязаны промпт, разбор ходов во фронте и сбор тронутых
файлов для git-коммита (`agent._touched_paths`).

**Права агента — только PreToolUse-хуками** (`agent.py: _make_guards`).
`can_use_tool` затеняется `allowed_tools` и молча не работает. Bash агенту
запрещён целиком: git-коммиты делает сервер (`gitops.py`), не агент. Кодовая
база read-only автоматически — её нет в write-корнях. Хуки — про CLI; в своём
цикле те же проверки делает `agent_tools.Access`, которым пользуются и гарды,
так что правило одно на оба движка.

**Агент читает НЕ рабочую копию кодовой базы, а зеркало ветки**
(`code_mirror.py` → `data/code-mirror`): shallow (--depth 1) + partial
(--filter=blob:none) клон с sparse-checkout каталогов из `GD_CODE_PATHS`
(пусто — весь репозиторий); истории в зеркале нет. `GD_CODE_REPO` не задан —
зеркала нет вовсе: синк не запускается, `vaultlib.code_root()` возвращает
None, блок «Код проекта» в промпт не попадает, в `add_dirs` ничего не едет.
Сервер подтягивает ветку раз в `GD_MIRROR_SYNC_MIN` минут (fetch читает
только refs). Незакоммиченные правки и другие ветки агенту не видны.
Источник клона — file:// URL (`Path.as_uri()`): с голым путём git включает
хардлинк-режим и игнорирует --depth.

Для partial-fetch в ИСХОДНОМ репозитории должны быть включены две локальные
опции (`git config uploadpack.allowFilter true`, `uploadpack.allowAnySHA1InWant
true`) — иначе .git зеркала распухнет до полного снапшота. После
переклонирования исходного репозитория включить снова.

**Профиль проекта — в волте, не в коде.** `prompts.py` подставляет в промпт
содержимое `VAULT/PROJECT.md` (чем занимается команда) и ссылается на
`VAULT/CODE_MAP.md` (карта репозитория). Оба сеются шаблонами из `vault_seed/`
при первом старте и правятся в веб-редакторе. Предметную специфику в
`prompts.py` не возвращать.

**Правила видимости путей волта — только в `vaultlib.py`** (can_see/can_write/
agent_scopes). Ими пользуются и хуки агента, и HTTP-ручки, и дерево UI. Новую
проверку писать туда, а не в server.py.

**Волт — отдельный git-репозиторий** (`vault/`, в .gitignore приложения).
Все вызовы git — через `gitops.py` под одним asyncio.Lock. Ход агента коммитит
только тронутые файлы (пути собираются из ToolUseBlock), хеш лежит в
`agent_turns.commit_hash` — diff хода это `git show <hash>`.

**Стриминг — NDJSON поверх POST** (`/api/chats/{id}/send`), не SSE и не WS.
`AuthMiddleware` — pure-ASGI: BaseHTTPMiddleware буферизовал бы стрим.
Остальные участники чата получают обновления поллингом `/api/changes?since=`
(таблица `changes`), стримящийся текст агента дописывается в `messages`
с троттлингом ~1.5 с.

**Созвоны (#86) — единственный WebSocket** (`/api/call/ws?chat=`), только
сигналинг WebRTC-mesh (медиа ходит P2P/TURN мимо сервера). AuthMiddleware
websocket-scope НЕ проверяет — авторизация по куке внутри хендлера `call_ws`.
Активные комнаты — в памяти (`server.py: CALLS`); факт «идёт звонок» подмешан
полем `calls` в `/api/changes`, в таблицу `changes` высокочастотное не льётся.
Каждый участник пишет свой микрофон (MediaRecorder, opus) чанками в
`POST /api/call/{id}/rec` → `data/calls/{call_id}/{uid}_{session}.webm`;
финализация (грейс 60 с) регистрирует дорожки как uploads и постит системное
сообщение с вложениями. ICE-конфиг — `GET /api/call/ice` из env
(GD_STUN_URL / GD_TURN_URL+USER+PASS / GD_ICE_JSON). Фронт — `web/call.js`;
getUserMedia требует HTTPS, по http кнопка звонка скрыта.

**Расшифровка созвонов (#88)** — после финализации `transcribe_call.py`
запускается под venv внешнего ASR-пайплайна (`GD_TRANSCRIBE_DIR`; там
onnx_asr + модель, CPU; диаризация не нужна — дорожки пер-спикерные, оффсеты
в `meta.json` рядом с webm). Каталог не задан или отсутствует — расшифровка
тихо выключена, звонки работают. Реплики постятся в ТРЕД под системным
«Звонок завершён» от имени говоривших (`author_kind="user"`); агент через
store.add_message НЕ вызывается. Очередь — `_TRANSCRIBE_LOCK` (по одному
звонку), таймаут час, ошибка — системным сообщением в тред.

**Авторизация Claude-движка — подписочная** (`common.py: setup_auth`): токен
`claude setup-token`. Ищется по `GD_CLAUDE_TOKEN_FILE`, затем `auth_token.txt`
в корне (в .gitignore). Файл читается при каждом создании сессии —
перевыпустил токен, сервер перезапускать не надо.

**Resume:** `sdk_session_id` из ResultMessage хранится в `agent_sessions`;
клиент чата закрывается по 30-минутному бездействию и пересоздаётся с
`resume` — контекст переживает и таймаут, и рестарт сервера. У своего цикла
resume нет: история ходов лежит в `agent_history` (строка = ход целиком,
чтобы обрезка по бюджету `GD_HISTORY_CHARS` не рвала пары tool_call/tool).
Контексты движков раздельные — после переключения провайдера агент опирается
на контекст ленты чата, который сервер кладёт в промпт каждого хода.

**Фронтенд** — ванильный JS без сборки и CDN, пути к API относительные
(работает и за реверс-прокси-префиксом). Markdown и diff рендерятся своими
мини-функциями (`web/md.js`, `web/diff.js`); сторонние библиотеки — только
вендорингом в `web/vendor/` (CodeMirror 5, Toast UI; список и лицензии —
THIRD-PARTY.md; без этих файлов редакторы тихо откатываются на textarea).

**Кэширование статики** (проект живёт и за реверс-прокси): `index.html`
отдаётся роутом `index_page` с `?v=<mtime>` на каждом js/css и `no-cache`;
остальная статика — `immutable` на год (`ImmutableStatic`). Менять схему
ссылок на ассеты — только через `_ASSET_RE`. Новые css/js в index.html
подхватываются сами; ассеты, подключаемые МИМО index.html, так кэшировать
нельзя. Загрузки чата (`/api/upload/{id}`) тоже `immutable` — имя файла
случайное, содержимое не меняется. Сжатие и HTTP/2 — на реверс-прокси.

**Темы** — токены в `:root` style.css, светлая — `[data-theme="light"]`.
Атрибут на `<html>` ставит инлайн-скрипт в `<head>` index.html ДО загрузки
стилей (иначе вспышка тёмного), выбор в localStorage `gd_theme`. Визуал
уровня «серьёзного ПО» — новые элементы UI строить на токенах, не хардкодить
цвета.

## Грабли Windows

- `common.py` при импорте чинит UTF-8 в консоли и выключает QuickEdit (клик
  мышью в cmd замораживает процесс вместе с пайпами SDK).
- Транспорт SDK — построчный JSON; `max_buffer_size` поднят до 64 МБ (Read
  картинок гонит base64 одной строкой).
- curl на localhost может врать из-за VPN — доверять логам сервера.
